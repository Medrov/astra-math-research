# MSC · Атлас математики

Локальное рабочее пространство с тремя связанными представлениями:
**области MSC → объекты и переходы → доказательство**.
На 31 октября 2026 лаборатория хранит версии математических постановок,
предлагает ограниченные наборы связей через Astra/Codex и проверяет все
обязательства выбранного перехода в Lean. В основном списке — два примера:
полиномиальный шаг из arXiv:2610.38474v1 и наша опубликованная связь ассоциатора
с энергией графового лапласиана. Сравнение двух загруженных файлов
в интерфейс не возвращено.

Процесс использует LangGraph с SQLite и ограниченные роли по мотивам Goedel-Architect.
Это собственная реализация графа обязательств, не подключение готового движка Goedel-Architect.
Метод, границы корпуса и смысл статусов: [RESEARCH_METHOD.md](RESEARCH_METHOD.md).
Устройство графов, версии, сертификаты и HTTP API: [OBJECT_GRAPH.md](OBJECT_GRAPH.md).
Исходное предложение сохранено в [RESEARCH_WORKSPACE.md](RESEARCH_WORKSPACE.md).

## Запуск

Нужны Git, Python 3.12 и Lean/Lake через elan. Из корня клонированного репозитория
сначала выполните `lake update` и `lake exe cache get`. Проект закрепляет Lean
4.19.0 и mathlib `c44e0c8ee63ca166450922a373c7409c5d26b00b`.
Нужные модули `MathResearch` для примера ассоциатора собираются заново внутри
проверки этого примера; полная сборка исторических 11 модулей для запуска UI не нужна.
Проверенные версии Python/Node/Codex и полный путь от клонирования до запуска —
в [корневом README](../../README.md#окружение).

На Windows из корня репозитория, в PowerShell:

```powershell
cd apps/msc-lean-atlas
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-research.lock
.\start.ps1 -Port 8765
```

`start.ps1` включает UTF-8 для Python и дочерних процессов, добавляет
пользовательский `~/.elan/bin` в PATH и определяет компилятор через `elan which lean`
только на время запуска. Явный `ATLAS_LEAN` сохраняет приоритет. Закрытие сервера —
`Ctrl+C`. Если политика PowerShell запрещает локальный скрипт, можно запустить
`powershell -NoProfile -ExecutionPolicy Bypass -File .\start.ps1 -Port 8765`;
это не меняет постоянную политику системы.

Проверки на Windows после установки Lean/mathlib (из папки приложения):

```powershell
$env:PYTHONUTF8 = '1'
$env:ATLAS_LEAN = (& "$env:USERPROFILE\.elan\bin\elan.exe" which lean).Trim()
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
npm.cmd run test:graph
```

Linux/macOS:

Из корня клонированного репозитория подготовьте окружение приложения:

```sh
cd apps/msc-lean-atlas
python3.12 -m venv .venv
.venv/bin/pip install -r requirements-research.lock
export PYTHONUTF8=1
export ATLAS_LEAN="$(elan which lean)"
./start.sh --port 8765
```

Открыть <http://127.0.0.1:8765/#map> или <http://127.0.0.1:8765/#research>.
Карта доступна сразу. Для Lean-проверок сначала подготовьте корневой проект по
[инструкции](../../REPRODUCE.md). По умолчанию приложение ищет Lean в PATH,
mathlib — в `.lake/packages/mathlib` корневого проекта. Для другой установки
задайте `ATLAS_LEAN`, `ATLAS_MATHLIB`, `ATLAS_PROJECT_ROOT` перед запуском.
Состав опубликованной копии и ограничения воспроизведения: [PUBLICATION.md](PUBLICATION.md).

Классификатор и графовые библиотеки включены локально, карта работает без интернета.
Для проверок нужен Lean/mathlib; пути задаются `ATLAS_LEAN`, `ATLAS_MATHLIB`,
`ATLAS_PROJECT_ROOT`. Для запуска Astra нужна существующая авторизация Codex
и доступ к точной модели `gpt-6-astra`; подмена модели не выполняется.
Путь CLI можно указать через `SHAIM_CODEX_BIN` (см. [контракт адаптера](CODEX_ADAPTER.md)).
Сервер слушает localhost. Старые ссылки `?run=…#lean` переводятся на карту;
сохранённые отчёты при этом не загружаются и компиляция не запускается.

## Исследовательский процесс

Выберите рубрику → «Исследовать» или откройте раздел «Исследования».
Кнопка **«Проверить связь»** открывает готовый пример или собственный вопрос.
Узел объекта показывает определение, параметры, условия и MSC-метки; узел
перехода — исходные и целевые объекты, преобразование, условия и обязательные
формальные цели. Нажмите **«Проверить выбранный переход»**, затем
**«Открыть граф лемм»** или отдельное обязательство, чтобы увидеть его основания.
Сам выбор другого перехода не переносит на него результат предыдущей проверки.

В основном списке доступны ровно два подготовленных примера:

| Пример / `case_id` | Что проверяет Lean |
|---|---|
| **Полиномиальный граф → координатная ось** / `arxiv_2610_38474_graph_subtraction` | Заключительный шаг §9.1 работы A. S. Frolov и I. S. Dorofeev, arXiv:2610.38474v1: обе композиции обратных преобразований и образ графа как равенства полиномов. [Материалы](examples/arxiv_graph_subtraction/README.md). |
| **Ассоциатор ↔ энергия графового лапласиана** / `published_associator_laplacian` | Равенство двух энергий из нашего [препринта v1.5](../../docs/Preprint.pdf) в конкретной рациональной модели. [Исходные адаптеры](examples/astra_energy/) используют опубликованную теорему `MathResearch.AlbertSpectralGeometry.associatorDirichlet_graphLaplacian`. |

Локальный пилот компилирует подготовленный исходник, а сертификат связывается
с точными обязательствами выбранного перехода. Учебная градиентная оценка,
строгое неравенство и контроли графовой энергии сохранены как внутренние тестовые
задачи; они не представлены как дополнительные основные примеры.

Кнопка **«Предложить связи»** принимает вопрос и MSC-метки. Один ограниченный
этап Astra предлагает до трёх переходов на графе не более чем из восьми объектов.
Они сохраняются как гипотезы: выберите переход и начните его проверку отдельно.
Просмотр карты, примеров, графов и результатов модель не вызывает.

В блоке **«Источник arXiv»** вставьте явную ссылку или ID и нажмите
**«Импортировать статью»**. Импорт не вызывает модель: он сохраняет конкретную
версию, метаданные, исходный HTML, разделы и формулы из MathML/LaTeX.
**«Сохранённая статья»** и **«Область извлечения»** выбирают локальный снимок
и раздел. **«Выделить объекты и переходы»** подготавливает вопрос; запуск Astra
выполняется отдельной кнопкой после проверки бюджета. Для статьи сервер допускает
до шести переходов и двенадцати объектов. Если весь выбранный текст не помещается
в бюджет, отчёт `source_scope` перечисляет фактически переданные фрагменты;
результат не считается извлечением всей статьи.

Связь из статьи сначала помечается как **«Утверждение статьи»**: Lean-постановки
у неё ещё нет. **«Формализовать и проверить»** создаёт отдельный производный граф
с точными целями, сохраняя исходную литературную карточку. Если точную цель
подготовить не удалось, `needs_review` останавливает работу с итогом `unknown`.
Наличие ссылки или импортированного текста не даёт сертификата Lean.

Для [arXiv:2610.38474v1](https://arxiv.org/abs/2610.38474v1) выбран небольшой шаг
из [§9.1](https://arxiv.org/html/2610.38474v1#S9.SS1): над произвольным коммутативным
кольцом и при `b,w ∈ R[t]` преобразование `S(x,y,z)=(y,x−b(y),z−w(y))` имеет
обратное `S⁻¹(T,X,Z)=(X+b(T),T,Z+w(T))` и переводит уже заданный граф
`(b(t),t,w(t))` в `(t,0,0)`. Пилот задаёт три обязательства как равенства полиномов.
Предшествующее приведение произвольной кривой к этому графу, формулы узлов и
мотивная часть статьи в его контракт не входят.

Список **«Графы объектов»** открывает сохранённые графы; переключатель версии
показывает прежнюю постановку вместе с её свидетельствами. **«Уточнить постановку»**
создаёт новую версию, сохраняя историю. Редактор позволяет изменить описания,
условия и формальные цели. Изменение русского текста не переписывает Lean-тип:
проверьте раздел «Формальная постановка Lean» или используйте «Новый вопрос для Astra».
Изменённая постановка больше не использует подготовленный пилот как своё доказательство.

Локальный корпус содержит подготовленные постановки и литературные карточки.
Снимок библиотечного индекса от 30 октября содержал 179 213 текстовых деклараций
из 6 315 файлов mathlib/MathResearch. Индекс создаётся локально после установки
Lean/mathlib; заголовок декларации не является свидетельством её применения
к новому вопросу. Сетевой доступ к arXiv выполняется только при явном импорте;
глобальный поиск статей по теме и автоматический обход ссылок не подключены.
Повторный импорт зафиксированной версии использует сохранённый снимок.
Статья без доступного HTML возвращает ошибку; PDF/OCR не подменяет её текст.
Локальный поиск не пересобирает индекс скрытно.
После неудачной Lean-проверки перед второй попыткой доказать лемму выполняется
дополнительный локальный поиск по её типу и диагностике. Запрос, результаты и
манифест корпуса сохраняются для этой леммы и версии плана; продолжение использует
сохранённую выборку. Пересборка индекса:

```sh
.venv/bin/python -c 'import research_retrieval; print(research_retrieval.build_index())'
```

На Windows та же команда выполняется через `.\.venv\Scripts\python.exe -X utf8`.

- **Проверить пилот — локально:** воспроизводит подготовленный Lean-исходник, без модели.
- **Один исследователь:** один контекст Astra строит план доказательства и исправляет его
  по Lean-ошибкам; предложение объектов и предварительная проверка постановки — отдельные вызовы.
- **Команда ролей:** планировщик, критик, отдельные исполнители лемм и проверка смысла.
  Независимые леммы выполняются параллельно, максимум две одновременно.

Запуски модели передают вопрос, выбранный математический контекст и найденные
карточки в Codex. Открытие карты и просмотр результатов модель не вызывают.
Настройки ограничивают вызовы и общее время; фактические токены учитываются отдельно.
Графы и их версии лежат в `research_data/objects.sqlite`, исследования, SQLite
checkpoints и артефакты — в `research_data/<id>/`, статьи — в `research_data/arxiv/`.
Остановка сохраняет результаты. После перезапуска сервера незавершённая работа
помечается прерванной; «Продолжить» использует сохранённый этап и ID попыток.
Неизвестный исход внешней отправки не повторяется автоматически.

Граф объектов допускает циклы и переходы с несколькими входами/выходами.
Это не граф зависимостей доказательства. Граф лемм использует Cytoscape + Dagre.
До проверки его рёбра обозначают план;
после успешной сборки показываются зависимости, извлечённые из Lean environment.
Исходники, логи, аудит аксиом и точный тип цели доступны в карточке результата.
`formal_outcome` относится к Lean-цели; `outcome` дополнительно учитывает проверку
соответствия замыслу. Модельная проверка смысла не является формальным сертификатом.

Для статуса перехода `proved`/`refuted` недостаточно одной удачной леммы:
нужны итоговая композиция, аудит аксиом и проверка типов всех обязательных целей.
Изменение определений, условий, цели или окружения требует новой проверки.
Косметическая новая версия может сохранить сертификат только при точном
совпадении семантического хеша и окружения. Неудачная повторная попытка остаётся
в истории и не удаляет уже проверенное свидетельство той же постановки.

## Проверки текущего этапа

Python-проверки выполняются командами из раздела запуска. Дополнительно:

```sh
npm run test:graph
node tests/test_object_graph.cjs
```

Свежий итог координатор сохраняет в `verification/object-graph-summary.json`.
Если файла нет, полный контрольный прогон в этой копии ещё не опубликован.
Старые числа тестов и отчёты ниже относятся к отмеченным историческим этапам;
они не подтверждают состояние новой версии. Платные вызовы модели не нужны
для обычных unit-тестов и локальных Lean-пилотов.

Для опубликованной версии используйте переносимые
[release-summary.json](checks/release-summary.json) и
[arxiv-study.json](checks/arxiv-study.json). История разработки в `verification/`
остаётся локальной и не переносится в свежий clone автоматически.

## Интерактивная карта

Отрисовка, выбор, масштабирование, перетаскивание и перемещение камеры выполняются
**Cytoscape.js 3.34.4**. Координаты рассчитывает **fCoSE 2.2.0**. Самодельная
отрисовка SVG-плиток и ограничение графа на 12 узлов удалены.

- Один клик выбирает рубрику; двойной клик или «Открыть ветвь» показывает её
  потомков. Для конечной рубрики видны соседние темы в её подразделе.
- Поиск работает по всему MSC. В полном режиме найденный узел приближается
  без удаления остальной карты; в обзоре поиск открывает нужную ветвь.
- Отсылки MSC включаются отдельно. Типы, направления и исходные оговорки
  сохранены; наведите курсор на ребро, чтобы прочитать их.
- Колесо/жест меняет масштаб, перетаскивание фона перемещает карту, узлы можно
  двигать. Кнопка рамки вмещает текущую карту; клавиши `+`, `−`, `0` работают
  при фокусе на графе. Изменение размера окна не перестраивает раскладку.
- Полный режим содержит 6604 отображаемых узла (6603 рубрики + центр) и при
  включённых отсылках 9935 рёбер (9872 исходных + 63 навигационных).

### Исследование связей в стиле Obsidian

Паттерны взаимодействия взяты из [Obsidian Graph view](https://help.obsidian.md/plugins/graph):
цветовые группы, выделение соседей и локальный граф. Рендеринг остаётся на Cytoscape.

- Девять цветовых групп помогают отличать области математики. Это редакционная
  группировка для навигации, не дополнительный уровень официального MSC.
  Все 63 основных раздела отнесены ровно к одной группе в `web/graph-presentation.js`.
  Первый клик по группе оставляет только её, следующие добавляют или убирают группы;
  снятие последней возвращает все. «Сбросить фильтры» также возвращает весь набор.
- «Локальные связи» открывают окружение выбранной рубрики на 1–3 реальных шага.
  При первом входе в режим включаются отсылки; их можно отключить. Обход учитывает
  оба направления рёбер для поиска соседей, но направления и типы исходных рёбер
  при отрисовке сохранены. Виртуальный центр исключён из обхода, поэтому через него
  не возникают искусственные короткие пути между разделами.
- Наведение выделяет соседей и приглушает остальные узлы. Карточка выбранной рубрики
  содержит переходы к связанным рубрикам. При уходе курсора подсветка снимается.
- Кнопки «назад/вперёд» возвращают выбранный узел, режим, глубину, фильтры и камеру.
  История хранится до перезагрузки вкладки. Новая ветка просмотра очищает переходы вперёд.
- Звезда сохраняет рубрику между перезагрузками на этом устройстве. Закладки,
  выбор цветного/монохромного режима и вид подписей записываются в localStorage.
- Настройки позволяют отфильтровать конкретный основной раздел MSC, выбрать код
  или код с названием, отключить цвет и подсветку соседей. Фильтры применяются
  совместно; пустой результат явно отмечается, исходные данные не меняются.
- Кнопка разворота выделяет графу рабочее пространство; Esc возвращает обычный вид.
  Стрелки клавиатуры двигают камеру, Alt+←/→ перемещают по истории при фокусе на графе.

Проверки этой итерации: `npm run test:graph` (17 проверок модели и цветов),
`node verify_obsidian.cjs` (15 реальных браузерных сценариев без моков и POST).
Отчёт: `verification/obsidian-functional.json`; снимки: `verification/obsidian/`.

Координаты обзора и полного графа сохранены в `web/graph-layouts.json`, чтобы
не рассчитывать большой граф при открытии. Ветки рассчитываются в Web Worker;
интерфейс не блокируется. Расстояние между узлами — результат раскладки, а не
оценка математического сходства. Позиции, изменённые пользователем, хранятся в
памяти вкладки и сбрасываются при перезагрузке.

Для пересборки библиотек и координат нужен Node.js:

```sh
npm ci --ignore-scripts
npm run build:graph
npm run test:graph
```

Версии закреплены в `package-lock.json`; браузер загружает готовый локальный
`web/vendor/graph-libs.min.js` без CDN. Лицензии MIT находятся в
`web/vendor/LICENSES.txt`. Метаданные раскладки содержат версии и хеш данных.
Реальные браузерные проверки: `node verify_graph_library.cjs` (Playwright
из установленного в этой среде runtime). Отчёт:
`verification/graph-library-functional.json`.

Официальные источники: [Cytoscape.js](https://js.cytoscape.org/),
[fCoSE](https://github.com/iVis-at-Bilkent/cytoscape.js-fcose).

## Сохранённый Lean-прототип: вход и выход

Вход: два исходника, необязательные полные имена целей, выбранные MSC-коды и
подготовленный контекст. Импорты вне этих двух файлов должны быть доступны в
указанном проекте/библиотеках. Имена модулей в прототипе используют латинские
буквы, цифры и `_`; текст Lean и имена деклараций могут содержать Unicode.

Почему файл и объект — разные вещи, что означает определение структуры и что
именно проверяет Lean, описано в [OBJECTS.md](OBJECTS.md).

В `runs/<id>/` сохраняются исходный запрос, семантическая инспекция и анализ.
Каждая проверка создаёт собственную папку с Bridge, журналами, скомпилированными
артефактами и отчётом. Неудачная новая проверка заменяет прежний текущий статус.
Отчёты доступны в файловом архиве и через прежний локальный API; формы сравнения в интерфейсе больше нет.

Навигационный путь (`navigation_only`) не является математическим переносом.
Для тематических маршрутов служебные рубрики с дефисом и общие исторические
разделы не используются как транзитные узлы; они сохранены в полном графе.
Литературная подсказка не доказывает применимость к загруженной паре.
Статус `verified` означает проверку **конкретной теоремы** с указанными
зависимостями. Участие обоих входов — необходимая структурная проверка, но оно
не гарантирует полезности связи: конъюнкция двух независимых фактов тоже может
использовать оба входа. Содержательность, адекватность предпосылок и новизна
оцениваются отдельно.

Компиляция использует готовые внешние `.olean`-кэши. Это не свежая сборка всей
mathlib или всех исходников исторического проекта. Детали — `examples/README.md`.

## Командная строка сохранённого Lean-прототипа

```sh
python3 cli.py demo astra-energy --verify
python3 cli.py demo definition-equality --verify
python3 cli.py demo unrelated-proof --verify
python3 cli.py analyze /path/A.lean /path/B.lean --project-root /path/project --targets A.object B.object
python3 cli.py verify ANALYSIS_ID /path/Bridge.lean --targets Bridge.correspondence
```

Для отрицательного примера ожидается ненулевой код завершения проверки.

## Данные и воспроизводимость

`data/MSC_2020.csv` и `data/MSC_2020.tex` — сохранённые официальные источники.
Все 6603 кода и 3114 буквальных отсылок сверены между форматами. На вводной
странице сайта указаны иные суммарные числа; расхождение записано в `meta`, а
содержимое выгрузок не подгонялось под них. Один указатель «--04 in that area»
сохранён как контекстное правило: без конкретной области он не задаёт ребро.

```sh
python3 import_msc.py            # повторная сборка из сохранённых источников
python3 import_msc.py --refresh  # новое скачивание с официального сайта
python3 -m unittest discover -s tests -v
```

Lean-тесты используют реальный подготовленный компилятор и пропускаются с явной
пометкой, если он отсутствует. Браузерные проверки и фактический сквозной результат
сохраняются отдельно в `verification/` и `web/qa/`.

MSC2020: Mathematical Reviews / American Mathematical Society и zbMATH,
[CC BY-NC-SA 4.0](https://creativecommons.org/licenses/by-nc-sa/4.0/).
Полная атрибуция, описание преобразований и условия — `data/ATTRIBUTION.md`.
Другие источники и их ссылки сохранены в `catalog/bridges.json` и примерах.

Прототип рассчитан на свои доверенные Lean-проекты на локальной машине.
Компиляция Lean-исходника допускает выполнение его compile-time команд;
это не сервис для исполнения чужого кода из интернета.
