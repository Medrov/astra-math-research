# QED role instructions

The eight prompt files in this directory and the MIT license are vendored unchanged from [proofQED/QED at bf91aaf](https://github.com/proofQED/QED/tree/bf91aaf8daa763281bdf0dafb46457fc794c11a5). Copyright © 2026 proofQED. See [LICENSE](LICENSE).

[SHAIM's adapter](../research_qed.py) selects the mathematical sections of each pinned prompt. It implements the survey and Easy exit, decomposition, proof writing, structural review and verdict, detailed review and final verdict, regulator decisions to revise the proof, revise the plan or rewrite, and the proof effort summary. The upstream reference implementations are [pipeline.py](https://github.com/proofQED/QED/blob/bf91aaf8daa763281bdf0dafb46457fc794c11a5/code/pipeline.py) and [decomposition_prover.py](https://github.com/proofQED/QED/blob/bf91aaf8daa763281bdf0dafb46457fc794c11a5/code/decomposition_prover.py).

SHAIM hands the task and the preceding stage reports to Astra through the local Codex App Server as text and reads a structured response. Survey findings use the supplied material. External literature lookup, shell work, file-based agent I/O and Lean verification are outside this runner. The controller persists stage outputs, counts attempts and tokens, honors cancellation and resumes completed turns by their immutable IDs. In addition to upstream revision bounds, the user's call and time budgets apply. An explicit counterexample can be returned for a false conjecture. By default an Easy answer is an unreviewed draft. SHAIM also offers an explicit full-route option. It preserves the original classification and passes the survey draft to the planner and prover, then follows the same review and revision stages as a nontrivial problem. The long branch may produce a model-reviewed draft. Formal certificates remain available in the separate SHAIM/Lean workflow.
