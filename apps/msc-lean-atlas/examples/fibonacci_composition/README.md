# Условный мост: шаг Фибоначчи и композиция квадратичной формы

Пакет сохраняет точное доказательство принятой постановки из исследования
4 ноября 2026 года по статье [A Pair of Diophantine Equations Involving the
Fibonacci Numbers, arXiv:2409.02933v1](https://arxiv.org/abs/2409.02933v1),
[§2](https://arxiv.org/html/2409.02933v1#S2), переход `quartic_step`.

На ℚ² заданы

```text
μ((u,v),(s,t)) = (us − vt, ut + vs)
N(u,v) = u² + v²
T(a,b,c) = ((b,a),(b,c)),  image = μ ∘ T.
```

Доказаны билинейность μ, представление N(x)=B(x,x) через билинейную B
и закон композиции N(μ(x,y))=N(x)N(y). Подстановка даёт
image=(b²−ac,b(a+c)). При **явных предпосылках** c=a+b и (b²−ac)²=1 получены

```text
(b² + a²)(b² + c²) = 1 + b²(a + c)²
2b⁴ − b²a² + a²c² = 1 + b²c².
```

Основная теорема — `CompositionBridge.conditional_transfer`. Полные точные
типы сохранены в [contract.json](contract.json) и [Contract.lean](Contract.lean).
Четыре обязательства:

| ID | Теорема | Содержание |
| --- | --- | --- |
| `structure` | `CompositionBridge.structural_laws` | Билинейность, квадратичность, композиция |
| `comparison` | `CompositionBridge.comparison_substitution` | Карта сравнения и точная подстановка |
| `transfer` | `CompositionBridge.conditional_transfer` | Условный перенос |
| `normalization` | `CompositionBridge.normalization` | Эквивалентности и нормализация выражений |

Конечное равенство не принято за гипотезу. Сравнение использует доказанный
закон композиции; перенос использует сравнение и нормализацию. Библиотечное
тождество `sq_add_sq_mul_sq_add_sq` переиспользовано явно в исходнике.

## Границы результата

Это условный алгебраический мост. Здесь нет определения последовательности
Фибоначчи и доказательства обеих предпосылок для соседних F при всех n≥2.
`source_application_status` остаётся **`not_verified`**. Вся статья, её полная
формула (1.7), существование или единственность диофантовых решений и научная
новизна не удостоверяются. **MSC 15A63 — предметное соответствие, предложенное
рецензентом (`inferred`), а не подтверждённая классификация источника.**

Сохранена принятая исправленная постановка. Формализатор выразил квадратичность
через диагональ билинейной формы; это не буквальное воспроизведение прежнего
отклонённого draft с отдельными формулами гомогенности и параллелограмма.

## Воспроизведение без модели

Нужны Python 3.10+, Git, Lean **4.19.0** и подготовленный mathlib на коммите
`c44e0c8ee63ca166450922a373c7409c5d26b00b`. Зависимости заданы в корневых
`lean-toolchain` и `lake-manifest.json`. После установки Elan и подготовки
зависимостей по корневому README выполните из корня репозитория:

```text
lake exe cache get
lake env python apps/msc-lean-atlas/examples/fibonacci_composition/verify.py
```

Если Python называется `python3`, замените только это имя. Если Lean отсутствует
в PATH, скрипт также принимает `--lean <путь-к-lean>` или `ATLAS_LEAN`; параметры
машинного окружения не сохраняются в этом пакете. Сторонние Python-пакеты не нужны.

Скрипт проверяет хеши, точные типы и закреплённые версии, создаёт новую папку
под `apps/msc-lean-atlas/verification/fibonacci-composition/`, заново компилирует
`Candidate.lean` и `Contract.lean` и выполняет восемь буквальных `#print axioms`
из `Axioms.lean`: для четырёх основных теорем и четырёх уравнений определений.
Допустимы только `propext`, `Classical.choice`, `Quot.sound`.
`Contract.lean` содержит пять проверок: основную цель и четыре обязательства;
совпадающая основная цель намеренно проверяется повторно.

Код завершения **0** и `success: true` в **новом** `verification.json` означают
успех этого повторения. Любая ошибка компиляции, неполный вывод аксиом, иной
хеш или версия дают отказ. Старые `.olean` этого примера не используются;
подготовленные внешние библиотечные кэши переиспользуются. Проверка не скачивает
зависимости, не вызывает модель и не повторяет смысловую рецензию.

Для проверки только целостности, без Lean:

```text
python apps/msc-lean-atlas/examples/fibonacci_composition/verify.py --check-only
```

Это **не** новая компиляция и **не** доказательный сертификат.

## Происхождение и сохранённая проверка

[Candidate.lean](Candidate.lean) и [Contract.lean](Contract.lean) скопированы
побайтно; их SHA256 соответственно:

```text
455648a0db4df2d99fc29cbcbea2779c44c0995bf99573bf662294c8b416c1d0
2a324f4240118af2cfc0b084756f0c7ccc39cc1c115dff89226506bf990f5a29
```

Локальная `.gitattributes` сохраняет байты Lean-файлов при клонировании.
[provenance.json](provenance.json) содержит источник, ограничения, хеши
артефактов и окружение. Машинных путей, модельных диалогов, сессий Codex,
локальной базы исследований и полного текста статьи в пакете нет.

[verification-reference.json](verification-reference.json) — очищенная
**историческая** запись. Исходный native proof потребовал 10 вызовов,
204464 токена и 1113.656 секунды. Это не Goedel-запуск. Сам экспорт и повтор
готового доказательства не требуют модели; они не являются слепым переоткрытием.
Seed исходной модели недоступен. Независимая пересборка сохранённого результата
дала три exit 0: Candidate, Contract и Axioms; проверены 4/4 обязательства.
Полный буквальный вывод аксиом включён в историческую запись.

Смысловая рецензия отдельно приняла условный механизм (`aligned`); компиляция
Lean и оценка новизны — разные проверки. После экспорта следует выполнить
новую команду выше: наличие исторической записи не заменяет свежий запуск.
Скрипт не добавляет этот пример в поисковый корпус и не изменяет MathResearch.
