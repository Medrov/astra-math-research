# Входные пары и формальная проверка

`astra_energy` — воспроизводимый положительный пример из уже опубликованного
проекта Astra. Два небольших модуля задают имена для энергии диагонального
ассоциатора и энергии графового лапласиана. `Bridge.energy_correspondence`
повторно использует известную теорему `associatorDirichlet_graphLaplacian`.
Это проверка рабочей цепочки на известном соответствии, не слепое открытие.

Область утверждения: конкретная рациональная 27-координатная модель, три
вершинных значения, веса `(dᵢ-dⱼ)²/4`. Не утверждаются полная формализация
алгебры Альберта, соответствие произвольных графов и алгебр, или новизна.

`unrelated` — отрицательный контроль. Оба файла импортируются в Bridge,
но теорема `1 = 1` не зависит от объектов пары. Lean принимает теорему;
сервис возвращает `unrelated`, `success: false` для связи двух входов.

Для своих файлов сохраняйте имена модулей: `Demo/InputA.lean` соответствует
`import Demo.InputA`. Входы могут импортировать друг друга без циклов. Остальные
импорты должны быть доступны в указанном подготовленном проекте и библиотеках.
Имена файлов в прототипе состоят из латинских букв, цифр и `_`; декларации
внутри могут использовать Unicode. Выберите полные имена интересующих теорем
или определений — файл может содержать несколько объектов.

Инспекция компилирует оба входа в новой папке. Типы, зависимости, происхождение
деклараций и используемые аксиомы читаются из настоящего Lean environment.
Внутренние стадии компилятора `_cstage*` не являются пользовательскими объектами
и исключаются. При ошибке возможен лишь явно помеченный лексический список.

Проверка Bridge заново компилирует входы, сам Bridge и доверенный экспортёр
метаданных. Разрешены только стандартные аксиомы `propext`, `Classical.choice`,
`Quot.sound`. `sorry`, `admit`, собственные аксиомы, `unsafe` и `native_decide`
в Bridge не допускаются. Также проверяется транзитивное участие деклараций
обоих входов в типе или доказательстве каждой выбранной теоремы. Если в интерфейсе
выбраны конкретные входные декларации, проверяется участие именно этих имён;
другой helper того же файла не заменяет выбранный объект.

Последняя проверка является необходимым структурным условием, но не полной
оценкой математического смысла. Например, конъюнкция двух независимых фактов
тоже может использовать оба входа. Статус `verified` означает проверенную
формальную теорему с указанными зависимостями; содержательность, адекватность
предпосылок и научная новизна оцениваются отдельно.

Импортированные внешние библиотеки и существующий проект используют их
подготовленные `.olean`-кэши. Это не свежая сборка всех зависимостей. Версия Lean,
ревизия mathlib, manifest и проектный Git commit записываются в отчёт.
Проверка хранит хеши двух входов, исходника Bridge и скомпилированного Bridge;
изменение входа после анализа требует повторного анализа.
