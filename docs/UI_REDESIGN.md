# Рабочее пространство исследований

Изменение реализовано в ветке `codex/research-pipeline-ui`. Дизайн предназначен
для сценария «источник → найденная связь → точная постановка → доказательство →
результат», включая неудачную формализацию и подготовку новой версии.

## Референсы и решение пользователя

3 ноября 2026 года через Mobbin MCP выполнены три запроса:

- Screens: `Linear project overview`.
- Screens: `GitHub Actions workflow run`.
- Flows: `Notion viewing version history`.

Каждый запрос вернул `INVALID_ARGUMENT` и сообщение
`Mobbin MCP requires a paid plan. Upgrade at https://mobbin.com/pricing to continue.`
Изображения и ссылки на экраны получены не были. После этого пользователь явно
выбрал «Продолжить редизайн без Mobbin». Повторных попыток и покупки подписки
не было. Эта реализация основана на анализе собственного приложения, а не на
якобы просмотренных экранах Mobbin. Ответы сохранены в локальном
`runs/current/pipeline-upgrade-2026-11-03/mobbin-references.json`.

## Визуальная концепция

По дополнительному запросу пользователя от 3 ноября 2026 года основная палитра
заменена на чёрно-белую, затем уточнена как преимущественно белая.
Светлая постоянная навигация (`#fafafa`) отделяет карту математики от
исследовательской работы тонкой серой границей. Белое рабочее поле (`#ffffff`)
содержит белые панели с нейтральными серыми границами. Основное действие, текст и фокус —
графитовые (`#171717`); заголовки используют общий шрифт без засечек.
Дополнительные цвета остаются у областей MSC и статусов: зелёный у успешной
проверки, янтарный у остановки или необходимости уточнения. Цвет области MSC
сохраняет собственный смысл и не превращается в цвет сертификата.

Крупный заголовок нужен для исследуемого утверждения. Метаданные, версии,
лимиты и технические названия имеют меньшую плотную типографику. Формулы
прокручиваются внутри блока. Код раскрывается отдельно. На большом экране
explorer показывает список, карту и инспектор рядом; при меньшей ширине
панели перестраиваются последовательно.

## Контракты UI и backend

- `source_card` / `source_cards`: входы, выходы, операции, условия, вывод,
  границы, точная формулировка и `grounding`. Цитаты, предложенная абстракция
  и уточнение пользователя явно различаются. Отсутствующая разметка цитат
  сообщается пользователю.
- `source_lineage`: родитель, корень цепочки и причина новой версии.
- `draft_repair`: версия черновика и состояние ограниченного исправления.
- `proof_backend`: выбранный процесс проверки. Варианты читаются из
  `GET /api/research/backends`; недоступные варианты отключены. Выбор доступен
  и при подготовке источника, и в диалоге новой версии. Исторические запуски
  без этого поля обозначаются как SHAIM/native, с сохранением фактических метрик.
- `POST /api/research/runs/{id}/revise`: сохраняет новую версию с обязательной
  причиной и необязательными изменениями названия, утверждения и условий.
  Возвращённый `draft` открывается без запуска. Отдельная кнопка вызывает
  существующий `POST /api/research/runs/{id}/resume`.
- Каталог механизмов читается через `GET /api/research/mechanisms` и
  `GET /api/research/mechanisms/{id}`. Просмотр не вызывает модель и не
  удостоверяет применимость механизма к текущему источнику.

Количество направлений MSC не фиксировано текстами интерфейса. Направления
показываются по фактическому результату поиска.

## Проверки и границы передачи

Проверки интерфейсной логики находятся в `tests/test_research_workspace.cjs`
и существующих наборах guided/map/history/candidate tests. Они проверяют
независимость типов и доказательства, сохранение исходного графа, новую версию
без автозапуска, происхождение текста, безопасные ссылки и фильтры.

В `.gitattributes` закреплено сохранение точных байтов KaTeX CSS/JS/LICENSE.
Два локальных файла восстановлены к байтам upstream, которые уже были
закреплены манифестом: причина прежнего сбоя — преобразование LF в CRLF.

Полный Python/Lean запуск и визуальную проверку в браузере выполняет
координатор. JS-тесты не заменяют эту проверку и не вызывают модель.
Координатор отдельно выполнил исследования на существующей математической
теме; их фактические модельные расходы приведены в итоговом отчёте. Итог frontend-проверки и ограничения
фиксируются в `runs/current/pipeline-upgrade-2026-11-03/frontend.json`.

Финальная приёмка: 219 JS-тестов прошли, затем Computer Use проверил реальный
сценарий, историю, фильтры, клавиатуру и сравнение старого `Function.iterate`
с исправленным `Nat.iterate`. Обнаруженный конфликт глобальных экспортов
устранён разделением `ResearchWorkspace` и `ResearchWorkspaceView`; реальный
порядок загрузки скриптов покрыт интеграционным тестом. Карточки направлений
теперь соответствуют фактическому числу сохранённых маршрутов, включая 0, 1 и 4.
Подробные результаты и ограничения захвата узких экранов находятся в
`runs/current/pipeline-upgrade-2026-11-03/ui-acceptance.json`.

После смены палитры повторно прошли все 219 JS-тестов. Через Computer Use
проверены карта, результат исследования и история; на ширине 390 px
горизонтального переполнения нет. Скриншоты и журнал этого изменения находятся
в `runs/current/ui-monochrome-2026-11-03/`. Менялось только оформление;
новые модельные исследования не запускались.

Покрытие загружается read-only через GET /api/research/runs/{id}/atlas. Устаревший ответ другого run не может заменить текущий обзор; ошибка загрузки показывается явно вместо нулевых показателей. Данные карточек выводятся через textContent или существующий безопасный math renderer, без HTML из источников.

Проверка реализации — unit/fake-DOM и реальные browser exports из подключаемых файлов. Визуальная проверка настоящего браузера, работа сервера и общий suite остаются у координатора; этот документ не выдаёт их за уже пройденные.

The saved article-transition launch asks for its own visible bounded budget before starting. Defaults: 8 calls and 10 minutes; the acceptance operator can choose 20 calls and 30 minutes. Opening/cancelling the dialog spends no model calls. Compact atlas source provenance is labelled as one retained example per code, with the complete link set preserved in the immutable snapshot.
