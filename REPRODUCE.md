# Как проверить доказательства

Нужны Git, Python 3.9 или новее и Lean/Lake через установленный
[elan](https://github.com/leanprover/elan). Команды выполняются из корня этого
комплекта. Скрипты Python используют только стандартную библиотеку.

## Получить репозиторий

```sh
git clone https://github.com/Medrov/astra-math-research.git
cd astra-math-research
```

Для повторения работы с агентами после подготовки окружения перейдите к [пошаговому примеру](WALKTHROUGH.md).

## Подготовка зависимостей

```sh
lake update
lake exe cache get
```

Эти две команды используют сеть. `lean-toolchain` задаёт Lean 4.19.0,
а `lakefile.toml` закрепляет mathlib на коммите
`c44e0c8ee63ca166450922a373c7409c5d26b00b`.
Обычная структура Lake — `.lake/packages/mathlib` и соседние каталоги
зависимостей. Сгенерированный `lake-manifest.json` полезно сохранить при
публикации, чтобы явно зафиксировать весь граф зависимостей.

## Полная свежая проверка

```sh
python3 scripts/check.py
```

Самый затратный этап — конечные доказательства в `MathResearch/OctonionIncidence.lean`. При нехватке оперативной памяти он заметно замедляется; вывод компилятора может появиться только после завершения модуля. Окончательный результат определяют код завершения и новый отчёт.

Нужны уже подготовленные toolchain и кэш mathlib. Wrapper сам не скачивает
зависимости. Для иной готовой установки можно передать `--lean` и `--mathlib`:

```sh
python3 scripts/check.py --lean "$LEAN_BIN" --mathlib "$MATHLIB_DIR"
```

Здесь `LEAN_BIN` и `MATHLIB_DIR` — пути к вашей установке. Для mathlib должны
существовать соседние dependency-каталоги из его manifest и кэши используемых
зависимостей; отдельный
clone mathlib с вложенными зависимостями не соответствует этому размещению.

`check.py` до проверок аргументов записывает `success: false`, затем создаёт
чистую временную копию ровно 11 исходников и запускает
`scripts/verify.py`. Он проверяет весь проект, выводит зависимости аксиом,
сверяет хеши исходников, журналов и `.olean`, и только после этого атомарно
публикует `verification/verification.json` с `status: complete` и `success: true`.
При ошибке прежний успешный сертификат не остаётся результатом нового запуска.
Не запускайте несколько проверок параллельно в одном checkout.

Журналы сохраняются в `verification/*.log`, новые `.olean` — в
`.lake/build/lib/lean`. Пути команд внутри нового сертификата относятся к
временной копии и текущей машине; временная копия удаляется после завершения.
Ненулевой exit code означает неуспех, независимо от содержимого старых журналов.

Прямой вызов сохранённого `verify.py` оставлен для аудита исходной реализации.
Для новых проверок используйте wrapper: сам этот скрипт может завершиться
до перезаписи JSON. `lake build` также не создаёт наш сертификат и не заменяет
его дополнительные проверки.

## Как выглядит успешный результат

Команда завершается с кодом 0 и сообщает `PASS: 11 Lean files; 149 theorem/lemma declarations.` В новом `verification/verification.json` должны стоять `success: true`, `status: complete`, `full_project_coverage: true`, а список `results` должен содержать все 11 исходников. Для каждого результата требуется `exit_code: 0`; хеши относятся к реально проверенным файлам.

При ошибке прочитайте вывод команды и соответствующий журнал. Не заменяйте новый результат сохранённым файлом из `checks/`. Проверка готового комплекта не требует изменения формулировок или доказательств.

## Независимый конечный эксперимент

```sh
mkdir -p verification
python3 scripts/probe_experiment.py
```

Результат: `verification/probe_experiment.json`. Скрипт независимо проверяет
октонную арифметику на целых числах, каталог и фиксированные наборы проб.
Это экспериментальная проверка, а не Lean-доказательство и не поиск новых проб.

## Программы поиска проб

```sh
mkdir -p experiments/results
python3 experiments/q9_local_search_seed0.py > experiments/results/q9.txt
python3 experiments/q10_local_search_seed17.py > experiments/results/q10.txt
python3 experiments/q18_greedy_search_unseeded.py > experiments/results/q18.txt
```

Программы поиска находятся в experiments и запускаются независимо от проверки готовых доказательств.
Для q9 задан seed 0, для q10 — 17; версия Python также может влиять на
побитовое повторение псевдослучайного поиска. В q18 seed не сохранён и в коде
не задан: повторный запуск не обязан находить именно опубликованный 18-набор.
Seed 18 не вводился. Поиск q9 эвристический: неудача не доказывает
невозможность девяти проб. Проверка фиксированного 18-набора остаётся
детерминированной в `probe_experiment.py` и в Lean.

Итог контрольного запуска приведён в [checks/last-run-summary.json](checks/last-run-summary.json). В нём отдельно указано, выполнялись ли установка зависимостей, компиляция и поисковые эксперименты.
Свежая формальная проверка не удостоверяет историческую новизну или полную
формализацию E10, Monster VOA и общей graded A∞-теории.

Инструкция установки: [Lean и elan](https://lean-lang.org/install/manual/).
Команда получения кеша: [документация mathlib](https://github.com/leanprover-community/mathlib4/blob/master/Cache/README.md). Версия проекта закреплена отдельно; обновлять её для проверки исходного результата не нужно.
